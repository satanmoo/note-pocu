# 데이터 크기 변환 니모닉

## `cbw`: 바이트를 워드로 변환

![[Pasted image 20260317004341.png]]

Accumulator 전용 `CBW`, `CWD` 부호 확장 명령어는 모두 *accumulator 레지스터(AL, AX)* 에만 동작한다. 

오퍼랜드를 받지 않는다.

> [!quote] MASM 6.1 Programmer's Guide, Ch.4 p.90 
> "8086-based processors provide four instructions specifically for sign-extending. The four instructions act only on the accumulator register (AL, AX, or EAX)"

**부호 확장 (Sign Extension)**
- `AL`의 bit 7(부호 비트)을 `AH`의 모든 비트에 복사하여, 값과 부호를 유지한 채 바이트 → 워드로 확장한다.

> [!quote] MASM 6.1 Programmer's Guide, Ch.4 p.90 
> 
> "Sign-extending means copying the sign bit of the unextended operand to all bits of the operand's next larger size. This widens the operand while maintaining its sign and value."

### 실행해서 `cbw`의 동작 확인하기

```nasm
mov al, 41h
cbw ; AL을 AX로 확장
```

![[Pasted image 20260317012127.png]]

`mov al, 41h` 실행 후 `AL`의 값은 41이 되었다.

![[Pasted image 20260317012247.png]]

`cbw` 실행 후 `AH`의 값이 0으로 채워졌다.

```nasm
mov al, 10001111b ; AL에 8비트 값 로드
cbw ; AL을 AX로 확장
```

부호비트를 1로 바꾸고 실행해보자

![[Pasted image 20260317012554.png]]

`mov al, 10001111b` 를 실행했다. `AL`에 8Fh을 대입했다.

![[Pasted image 20260317012752.png]]

`cbw` 실행 후 `AH`의 값은 FFh로 채워졌다.

부호가 그대로 유지되는 것을 확인했다.

## `cwd`: 워드를 더블 워드로 변환

![[Pasted image 20260317012918.png]]

> [!NOTE] 축소하는 개념은 없다.
> 
> 아래 비트만 사용하면 되니까


*A 레지스터* 는 16비트인데 확장하면 나머지 16비트는 어디로 갈까?
- `dx`
- "extended"의 "d"


> [!quote] MASM 6.1 Programmer's Guide, Ch.4 p.90 
> 
> AX to DX:AX

### 실행해서 `cwd`의 동작 확인하기

```nasm
mov ax, 0F01Fh ; AX에 16비트 값 로드

cwd ; AX를 DX로 확장
```

![[Pasted image 20260317013657.png]]

`mov ax, 0F01Fh` 실행 결과 `AX`에 F01Fh가 저장됬다.

![[Pasted image 20260317013758.png]]

`cdw` 실행 후 `DX`의 값이 모두 1로 채워진 것을 확인할 수 있다.
