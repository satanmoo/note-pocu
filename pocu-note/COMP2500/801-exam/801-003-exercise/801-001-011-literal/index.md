# 리터럴

## 다음 코드가 컴파일 오류인 이유는?

```java
long big = 10_000_000_000;
```

정수 리터럴은 기본적으로 int로 해석됨

- `10000000000`은 int 범위를 초과 → long에 대입하더라도 리터럴 자체가 int로 평가되어 컴파일 오류
- long 리터럴임을 알리는 suffix `L`을 붙여야 함

```java
long big = 10000000000L;
```

## 정수 리터럴의 진법을 나타내는 prefix는?

- `0x` : 16진수
- `0b` : 2진수
- `0` : 8진수

## 부동소수점 리터럴의 suffix는?

- `f` / `F` : float
- `d` / `D` : double (suffix 없으면 기본 double)

## 문자열 리터럴의 유니코드 escape `\unnnn`에서 nnnn은 어떤 진법인가?

16진수 (hex)
- 유니코드 코드 포인트는 16진수로 표현하니

## null 리터럴은 어떤 자료형에서만 사용할 수 있는가?

참조 자료형

- 기본형(int, char 등)에는 사용 불가
