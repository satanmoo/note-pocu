# 기말고사 문제풀이 습관 로그

시험 문제 세트 풀기 전에 읽는다. 다음 세트에서도 재발하면 진짜 습관, 재발 없으면 삭제. 짧게 유지. (과제·실습용은 [[pocu-note/COMP2500/habit-log|습관 로그]] 별도)

- **재작성 문제는 부모의 public 메서드 목록부터 센다** — 오버라이딩 안 한 메서드도 상속으로 노출되던 클라이언트 API이므로 포워딩으로 전부 재노출. 답안 분량은 오버라이딩 개수가 아니라 부모 public 메서드 개수가 결정 (공식 1번: `doMagic()` 포워딩 누락, 2026-08-16)
- **상속 계층의 메서드 선언마다 부모 사슬(Object까지) 시그니처 대조 — 전수로, 첫 발견에서 멈추지 않기** — 매칭 기준은 ==이름·매개변수 목록==. 어노테이션은 대조를 면제해주는 게 아니라 결과 해석만 바꿈: 매칭 없음+`@Override` 있음 → 컴파일 오류 / 매칭 없음+없음 → 별개 메서드(오버로드, 부모 구현 실행 가능) / 매칭 있음 → 오버라이딩 (단, 매칭됐는데 반환형이 호환 안 되면 어노테이션 무관하게 컴파일 오류) (공식 2-a 오버로드 함정 통과, 2-b `WeirdCalculator`의 3매개변수 `subtract` 누락, 2026-08-16)
- **a/b/c 유형은 로직 추적 전에 선언부 정적 스캔 — 판정 먼저, 출력 추적은 "문제없음" 확정 후에만** — 스캔 대상: `final`(클래스 상속·메서드 오버라이딩·필드 재대입) / `abstract`(인스턴스화·바디·미구현) / 접근 제어자(축소) / checked `throws`·catch 순서. "꼼꼼히"라는 의지가 아니라 읽기 순서를 바꾸는 절차로 강제. 오류로 판정했으면 c) 출력은 적지 않기 — 적으면 감점 (공식 4번: `final` 2건을 못 보고 세트 최장 로직 추적 수행 + c 작성, 2026-08-16)
- **`HashSet`·`contains`·중복 판정이 보이면 `equals`와 `hashCode`의 존재를 각각 눈으로 확인** — 버킷 탐색은 `hashCode`, 최종 중복 판정은 `equals`. "`hashCode`·`toString`이 있으니 `equals`도 있겠지" 추론 금지 — 존재는 가정이 아니라 확인 대상 (공식 6번: `equals` 부재를 못 보고 중복 제거된다고 답함 — 정답은 4권 전부, 2026-08-16)
- **호출 읽기 규칙: 무늬는 출입 검사, 실행은 실체에서 위로** — 컴파일 타임엔 무늬(와 그 조상)에서 시그니처 존재·오버로드 해석만 확정하고 역할 끝. 런타임엔 ==실체 클래스에서 시작해 부모 방향으로 올라가며 처음 만나는 구현== 실행 (무늬가 바뀌어도 실행 결과 불변). `super.method()`는 이 탐색을 ==선언 클래스의 직계 부모에서== 컴파일 타임에 확정 — dispatch 없음, 실체 무관 (공식 2-c·3-b 통과, 프로토콜로 명시, 2026-08-16)
	- ==모든 호출에 예외 없이 적용== — 특히 어려운 축(equals 사슬 등)을 통과한 직후의 쉬워 보이는 마무리 호출(출력용 `getFullName()`·`toString()` 등)이 생략되기 쉬움 (공식 5번: equals 분석 후 `getFullName()` 대조 생략 → 실체 `Knight`의 "Sir " 누락, 2026-08-16)
- **필드와 매개변수 이름이 겹치는 메서드는 암산하지 않고 값 표를 타이핑으로 그린다** — `this.`가 붙은 항(필드)과 안 붙은 항(매개변수)을 행으로 분리해 값을 먼저 확정한 뒤 계산 (실전은 종이 불가 — 메모는 타이핑으로) (공식 8-b: `this.y`(필드 5)를 매개변수 `y`(2)로 치환해 7을 4로, 2026-08-16)
